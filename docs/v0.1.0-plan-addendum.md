# v0.1.0 Plan Addendum — Post-Plan Reality

This document summarizes what happened between the v0.1.0 plan (at `~/.claude/plans/users-redtropig-desktop-users-redtropig-concurrent-truffle.md`) and the actual v0.1.0 release (commit `bdb0f99`). The plan was implemented in 5 commits, with 3 gap-fix rounds.

## Gap-fix rounds

### Round 1 (`f099f6c`) — 2 plan-vs-implementation gaps

The initial implementation from the plan missed two items that the plan specified but the implementer overlooked:
- A specific validation check that was described but not coded
- A reference in a command file that pointed to a non-existent path

### Round 2 (`81c332f`) — 3 gaps (A, B, C)

Three more gaps identified during self-review:
- **A:** The `docs-lookup` skill was mentioned in the plan's "Web/Context7 search integration" section and referenced by other skills via "invoke docs-lookup", but no actual `skills/docs-lookup/SKILL.md` file had been created.
- **B:** A command file referenced a template path that didn't match the actual template filename.
- **C:** The `validate-anchor.sh` script was checking fewer items than the plan specified.

### Round 3 (`bdb0f99`) — docs-lookup extraction + polish

- **`docs-lookup` skill extraction** (`ba4e132`): Extracted the Context7 → WebSearch fallback chain from inline mentions across multiple skills into a dedicated `skills/docs-lookup/SKILL.md`. This skill is now the canonical procedure for unfamiliar tools/APIs/errors — other skills reference it instead of inlining the waterfall.
- **README rewrite and agent compression** (`bdb0f99`): Tightened README, compressed subagent prompts to fit within token budgets.

## Key deviations from the plan

1. **`docs-lookup` was not in the original plan.** It emerged during round 2 as a necessary extraction — the plan's "Web/Context7 search integration" section described the pattern but didn't call for a dedicated skill. The extraction was justified by the DRY principle and the plan's own invariant #9 ("docs-lookup is the canonical procedure").

2. **No CI workflow in v0.1.0.** The plan called for `.github/workflows/validate.yml`, but the initial commit only included the script (`validate-anchor.sh`), not the CI workflow. This was added later in v0.2.0 (Layer C).

3. **`scripts/escape-json.sh` was dead code from the start.** The plan listed it in the directory structure, but all four hooks inlined an identical `escape_for_json` function instead. It was removed in v0.2.0 (Layer B, DD3).

## Lessons for future planning

- **Gap-fix rounds are inevitable.** Even with a detailed plan, the translation from plan to code introduces oversights. Budget for at least 2 gap-fix rounds.
- **Extract shared procedures early.** The docs-lookup extraction should have been in the original plan. If multiple skills reference the same procedure, make it a skill.
- **Validate directory structure against actual references.** The `escape-json.sh` listing in the plan was never referenced by any hook — a grep for references would have caught this.
